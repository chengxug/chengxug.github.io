## 什么是进程

进程就是一个正在运行的程序，一个程序的运行实例。因为正在运行的程序比运行前的程序包含更多的信息，这些多出的信息帮助操作系统实现时分共享，造成同一时刻多个程序同时运行的假象，所以提出了进程这个概念。

我们知道，程序是就是存储在硬盘上的一个可执行文件，文件中只包含两部分内容：指令和数据；而进程——一个正在运行的程序，除了指令和数据之外，还包括寄存器的状态、标识进程的信息和进程所拥有的资源。

- 寄存器状态，比如程序计数器中存储下一条要执行的指令的地址，栈指针寄存器中存储的进程的栈空间的起始地址。
- 标识进程的信息：比如进程号 pid。
- 进程所拥有的资源：比如进程打开的文件、堆上申请的空间。

# 进程的状态

进程最基本的状态有三个：就绪态、运行态和阻塞态

![alt text](进程三态模型.png)

- 就绪态：进程已经被操作系统创建完成，准备就绪，等待操作系统的调度执行
- 运行态：进程占据 CPU 资源，正在执行
- 阻塞态：进程因为某些条件不满足而被操作系统阻塞，等待条件满足。

处于就绪态的进程被操作系统调度执行后就转为运行态；正在运行的进程会因为操作系统的调度而切换到就绪态，让出 CPU 资源，也可能会因为等待某些条件而切换到阻塞态；被阻塞的进程等到条件满足后不会立即执行，而是切换到就绪态，等待操作系统的调度。

在三态模型的基础上，加上程序的新建态和结束态就得到了进程的五态模型：
![alt text](进程五态模型.png)

- 新建态：操作系统正在执行创建进程的操作，创建完成后，进程进入就绪态
- 结束态：程序退出后（执行结束正常退出，或者因为违规操作被 kill 掉），进程就如结束态，操作系统销毁进程。

在基本的五态模型的基础上，还可以根据我们观察的重点，为进程添加更多的状态描述。例如，因为虚拟内存机制，进程可能会在内存和硬盘空间之间换入换出，当进程从内存被换出到硬盘空间时，我们称进程被挂起，所以添加就绪挂起态和阻塞挂起态，得到进程的七态模型：

* 就绪挂起态：就绪态的进程挂起到硬盘空间
* 阻塞挂起态：阻塞态的进程挂起到硬盘空间

![alt text](进程七态模型.png)

当内存空间不足时，待执行的进程（就绪态或阻塞态）被换出到磁盘，进程切换为挂起态。当就绪挂起态的进程将要被调度执行时，进程被换入到内存，切换为就绪态；当阻塞态的进程条件满足时，切换到就绪挂起态。

# 进程的数据结构

为了标识和管理进程，操作系统需要用一个数据结构来表示进程，我们把这个数据结构称为进程控制块（Process Control Block 简写为 PCB），PCB 中包含三种类型的信息：

1. 标识信息：用来标识一个进程，包括进程的 ID，进程所属父进程的 ID，进程所属用户的 ID
2. 状态信息：用来描述进程在 CPU 上的状态，实际上是程序运行时寄存器中的值，用来做进程切换。
3. 控制信息：操作系统对进程做控制的信息，比如进程当前的调度状态（就绪、运行等），进程所拥有的资源和资源的使用情况。

以 xv6 系统中的进程的数据结构为例。

```C
// 进程上下文，即CPU上的寄存器状态
struct context

{
    int eip; // 程序计数器 (Program Counter)
    int esp; // 栈指针(Stake Pointer)寄存器
    int ebx; // 基址寄存器 (Base)
    int ecx; // 计数器 (Counter)
    int edx; // 数据寄存器 (Data)
    int esi; // 源变址寄存器 （Source Index）
    int edi; // 目的变址寄存器 (Distination Index)
    int ebp; // 基址指针寄存器 （Base Pointer）

};

enum proc_state

{
    UNUSED,
    EMBRYO,
    SLEEPING,
    RUNNABLE,
    RUNNING,
    ZOMBIE
};

struct proc
{
    char *mem;                  // 进程内存空间的起始地址
    uint sz;                    // 进程内存空间的大小
    char *kstack;               // 当前进程内核栈的栈底
    enum proc_state state;      // 进程的状态
    int pid;                    // 进程号，唯一的标识一个进程
    struct proc *parent;        // 指向父进程pcb的指针
    void *chan;                 // 如果非0，进程在chan上睡眠
    int killed;                 // 如果非0，说明进程已被kill掉
    struct file *ofile[NOFILE]; // 进程打开的文件
    struct inode *cwd;          // 进程的当前目录
    struct context *context;     // 寄存器状态
    struct trapframe *tf;       // 发生中断时，CPU上的寄存器状态
}
```

进程的标识信息是 pid, 进程的状态信息是 context，其余字段是进程的控制信息。

# 操作系统如何创建一个进程

首先，操作系统创建表示这个进程的数据结构，然后初始化进程的内存布局，懒加载程序的代码和数据。至此进程创建完成，操作系统把进程的状态修改为就绪态，然后按照调度策略调度程序执行。

# 操作系统如何做进程切换

## 进程切换的时机

进程的切换时机分为两类：

1. 进程触发了执行切换的动作：
   1. 进程发起一个耗时的 IO 操作，操作系统修改进程状态为阻塞态，调度其他进程执行，等 IO 操作结束后，再修改进程状态为就绪态。
   2. 系统调用：进程发起系统调用，切换到内核态执行。
   3. 进程终止：进程正常结束或者因为异常操作而被操作系统 kill 掉，操作系统调度下一个程序执行。
2. 进程所拥有的时间片耗尽：操作系统在调度进程执行时，会为进程分配一个时间片，这个时间片说明进程可以占据多久的 CPU 资源，等到时间片耗尽，操作系统调度下一个进程执行。

## 操作系统在切换进程的时候做什么

操作系统切换进程时做三件事

1. 选中要调度新进程
   根据调度策略，选中下一个要执行的进程
2. 保存当前进程的状态
   保存当前进程的 CPU 状态到内存中，也就是保存 CPU 中各种寄存器的值，指令寄存器、栈指针寄存器等等
3. 加载新进程到 CPU
   从内存中加载新进程的状态到 CPU。（在之前的切换中，新进程的保存的寄存器的值）

以 xv6 操作系统为例，

```asm
pushl %edi
pushl %esi
pushl %ebx
pushl %ebp
movl %esp, (%eax)      # Save current ESP to old process's context

movl %edx, %esp        # Load new process's ESP
popl %ebp
popl %ebx
popl %esi
popl %edi
ret
```

# 总结一下

## 什么是进程

进程是一个程序的运行实例，比程序包含更多信息：寄存器的状态，标识进程的信息和进程所拥有的资源。

## 为什么要引入进程这个概念

为了提高 CPU 利用率，现代操作系统采用时分共享机制实现同一时刻多个程序共同执行的假象，程序的执行环境由顺序执行变为并发执行，单纯的程序（code + data）无法描述程序的并发执行，所以引入进程描述程序的并发执行。并且，操作系统对进程做一定管理，保证程序并发执行的结果可再现。

## 操作系统如何创建进程

1. 创建进程的数据结构
2. 初始化内存空间布局
3. 懒加载进程的指令和数据

## 操作系统在切换进程的时候做什么

1.  选中要执行的新进程
2.  保存当前进程的 CPU 状态
3.  加载新进程到 CPU
