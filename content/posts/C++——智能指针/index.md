智能指针（Smart Pointers）是 C++11 及更高版本中引入的，用于管理动态分配的内存（堆内存）的对象。它们的核心思想是**RAII (Resource Acquisition Is Initialization)**，即“资源获取即初始化”。简单来说，智能指针通过将资源（这里是动态内存）的所有权封装在一个对象中，当这个对象超出作用域时，它会自动释放所拥有的资源。

---
#### 为什么需要智能指针
在 C++ 中，我们使用 `new` 和 `delete` 来手动管理堆内存。这带来了很多问题：
1. **内存泄漏 (Memory Leaks)**：忘记 `delete` 或者在 `delete` 之前程序因异常退出，导致内存无法释放。
2. **野指针 (Dangling Pointers)**：指针指向的内存已经被释放，但指针本身没有被置空，再次访问该指针会导致未定义行为。
3. **重复释放 (Double Free)**：对同一块内存多次 `delete`，导致程序崩溃或未定义行为。
4. **所有权不明确 (Ownership Ambiguity)**：多个指针指向同一块内存，不清楚谁负责释放。

智能指针就是为了解决这些问题而生的，代替普通指针管理内存，确保资源在不再需要时被正确释放。

---
#### C++11 引入的三种智能指针

C++ 标准库提供了三种智能指针类型，它们在所有权语义上有所不同：
1. **`std::unique_ptr`：独占所有权，在任何时候，只有一个`unique_ptr`可以指向给定的动态内存**
2. `std::shared_ptr` ：**共享所有权**，多个 `shared_ptr` 可以共同指向同一块动态内存。
3. `std::weak_ptr` ：弱引用智能指针，它**不拥有所指向的资源**，用于协助 `shared_ptr`，解决**循环引用问题**。

##### 1. std::unique_ptr
###### **实现原理**
1. 实现基础——作用域 (Scope)
	在 C++ 中，作用域决定了变量的生命周期。当一个变量在某个代码块（例如，一个函数、一个 `if` 语句块、一个 `for` 循环体，或者简单的花括号 `{}` 之间）内声明时，它的生命周期就限定在这个作用域内。
	- 进入作用域：变量被创建（栈上分配内存，调用构造函数）。
	- 离开作用域：变量被销毁（自动调用析构函数，释放栈上内存）
2. 实现思路
	`unique_ptr` 就是利用了上述 C++ 的作用域规则和对象的析构函数来管理堆内存的。
	
	`unique_ptr` 的内部实际上封装了一个**裸指针**，这个裸指针指向了通过 `new` 或 `make_unique` 分配的堆内存。
	
	它的析构函数被设计成：当 `unique_ptr` 对象本身被销毁时，它会检查它是否还在管理着一块内存（即它内部的裸指针是否为 `nullptr`），如果管理着，它就会**自动调用 `delete` 来释放那块内存**。

###### **特点：**
- **独占所有权**: 不能被复制（`std::unique_ptr<T> u1 = u2;` 是编译错误）。
- **可以移动 (move)**：所有权可以通过移动语义 (`std::move`) 进行转移。转移后，原来的 `unique_ptr` 变为 `nullptr`。
- **轻量级**：通常和裸指针一样高效，因为它没有额外的引用计数开销。
- **自动释放**：当 `unique_ptr` 超出作用域时，它所管理的内存会自动被 `delete` 释放。
- **支持数组**：可以管理动态分配的数组 (`new T[]`)，通过 `delete[]` 释放。
###### **使用场景：**

- 当明确知道某个资源只会被一个所有者管理时。
- 作为函数返回值，将所有权从函数内部转移给调用者。
- 作为类成员，管理其内部资源。

##### 2. shared_ptr
###### **实现原理**
`std::shared_ptr` 实现**共享所有权**的核心在于**引用计数 (Reference Count)** 机制：在`shared_ptr`内部通过一个**引用计数 (reference count)** 来跟踪当前有多少个 `shared_ptr` 正在管理这块内存。当引用计数变为零时，即没有 `shared_ptr` 再指向这块内存时，内存就会自动被释放。
为了实现这个机制，`shared_ptr` 通常会维护一个额外的**控制块 (Control Block)。

* **控制块 (Control Block)**
	当一个 `std::shared_ptr` 被创建并开始管理一个对象时，它会同时创建一个控制块。这个控制块通常包含以下信息：
	1. **强引用计数 (Strong Reference Count)**：跟踪有多少个 `std::shared_ptr` 实例正在共享管理这个对象。当这个计数降到零时，表示不再有 `shared_ptr` 指向该对象，对象会被销毁 (`delete` 或自定义删除器)。
	2. **弱引用计数 (Weak Reference Count)**：跟踪有多少个 `std::weak_ptr` 实例正在观察这个对象。当所有 `shared_ptr` 都已销毁（强引用计数为零），但弱引用计数仍大于零时，对象会被销毁，但控制块会保留（因为它仍被 `weak_ptr` 观察）。当弱引用计数也降到零时，控制块才会被销毁。
	3. **被管理对象的指针 (Pointer to Managed Object)**：指向实际动态分配的对象的裸指针。
	4. **删除器 (Deleter)**：一个可选的函数对象（或lambda），用于在引用计数为零时销毁被管理对象。默认情况下是 `std::default_delete`，它会调用 `delete obj_ptr;`。
	5. **分配器 (Allocator)**：一个可选的分配器对象，用于分配被管理对象和控制块的内存。

* **`std::shared_ptr` 对象的内存布局：**
	一个 `std::shared_ptr` 对象本身通常只包含两个指针：
	1. 一个指向**被管理对象**的裸指针。
	2. 一个指向其对应**控制块**的裸指针。

* **销毁过程：**
	当任何一个 `shared_ptr` （比如 `ptr1`）超出作用域或被重置时，它的析构函数会被调用，它会**减少控制块中的强引用计数**。
	- 当强引用计数变为零时，`shared_ptr` 会调用其控制块中存储的**删除器**来销毁被管理的对象。
	- 之后，当弱引用计数也变为零时（如果存在 `weak_ptr`），控制块本身才会被销毁。
	这种机制确保了只要有一个 `shared_ptr` 还在管理对象，对象就不会被销毁。当所有 `shared_ptr` 都消失后，对象才会自动被清理。
###### **使用场景**
- 当多个对象需要共享同一块资源的所有权时。
- 管理资源的生命周期，直到所有使用者都完成。
- 在工厂函数中创建对象并返回，允许调用者共享所有权。
##### 3. `std::weak_ptr`
`std::weak_ptr` 是一种**弱引用**智能指针。它不拥有所指向的资源，因此不会增加资源的引用计数。它主要用于解决 `std::shared_ptr` 造成的**循环引用**问题。

###### **特点：**
- **不拥有资源**：不增加引用计数，因此不会阻止 `shared_ptr` 所管理的对象被释放。
- **不能直接访问资源**：它没有 `operator*` 或 `operator->`。要访问资源，必须先通过 `lock()` 方法获取一个 `shared_ptr`。
- **`lock()` 方法**：如果 `weak_ptr` 所指向的资源仍然存在（即有 `shared_ptr` 在管理它），`lock()` 会返回一个 `shared_ptr`；否则返回一个空的 `shared_ptr`。
- **主要用途**：打破 `shared_ptr` 之间的循环引用，防止内存泄漏。

###### **使用场景：**
- 当两个对象互相持有对方的 `shared_ptr` 时（即循环引用），将其中一方改为持有对方的 `weak_ptr`。
- 观察者模式中，观察者持有被观察者的 `weak_ptr`，避免被观察者被观察者生命周期绑定。
- 缓存管理，当缓存中的对象不再被其他 `shared_ptr` 引用时，可以被释放。
