# 虚拟内存

虚拟内存提供了一个抽象，把主存看作磁盘的缓存，只保存程序的活动区域在主存，在主存和磁盘之间来回传送数据，实现了对主存的高效使用。

## Prerequisite

对计算机内部的存储器层次有大致了解

## 内存访问方式

我们知道，计算机内部的存储器可分为三个层次：磁盘、主存和 CPU 高速缓存。其中主存就是我们口中常说的内存，主存的大小就是物理内存的大小。在逻辑层面，物理内存被视作由字节组成的数组，每个字节都有唯一的索引称为地址，因为这个地址直接对应物理内存中的特定位置，所以被称作物理地址。CPU 直接使用物理地址访问内存的方式被称为物理寻址。
![alt text](image.png)

早期的计算机就是使用物理寻址的方式直接对内存进行访问。但是这样操作遇到了以下问题：

1. 程序的内存空间不隔离
   在物理寻址的情况下，所有程序都直接对物理内存进行读写，一个程序很容易修改其他程序的内存空间，造成程序崩溃或修改程序行为。抛开恶意程序的攻击行为不谈，想象一下你写的程序崩溃不是因为你的问题，而是因为其他程序的 bug 引起的，这无疑是为程序的编写和调试带来了极大的困难。
2. 程序加载和运行困难
   每次程序加载时，内存空间的使用情况大概率是不同的，因此程序在内存中的起始地址也不相同，但是在可执行程序中，指令中对绝对地址的引用是固定的。这为程序的加载和运行带来了极大的困难。
3. 对内存的访问效率低
   运行一个程序时，内存的可用空间不足，就要对内存中的整个程序进行换入换出，造成对内存的访问效率低下。

因为以上问题的存在，现代的计算机大多数使用虚拟内存。
在虚拟内存机制下，磁盘被看作是由字节组成的大的数组，每个字节都有一个唯一的索引称为虚拟地址。磁盘内的数据缓存到主存中，CPU 生成虚拟地址，经过硬件翻译为物理地址访问主存，磁盘与主存之间来回交换数据。这种方式称为虚拟寻址。
![alt text](image-1.png)
虚拟内存提供了以下好处：

1. 每个进程拥有独立的虚拟地址空间，对内存的访问隔离。
2. 程序的起始地址固定，程序加载运行方便
3. 不同进程可以共享物理内存中的相同部分，节省内存使用。
   接下来，让我们详细看看计算机中的虚拟内存机制具体是如何实现的。

## 主存和磁盘上数据交换的过程

磁盘和主存上的数据被分割成大小固定的块，磁盘和主存之间的数据交换是以这个固定大小的数据块为单位的，这个数据块被称为“页”，磁盘上的数据块被称为虚拟页，主存中的数据块被称为物理页。虚拟页和物理页大小相同，分别有对应的页号。
![alt text](image-4.png)
磁盘上的虚拟页有三种状态：

1. 未分配的
2. 已分配但没有缓存到主存中的
3. 已缓存到主存中的。

操作系统内核在物理内存中维护着一个固定大小的页表，页表是由页表条目组成的数组。页表条目包含一个有效位和一个地址字段（这里只关注我们需要的），页表中的页表条目和磁盘中的虚拟页相对应：
![alt text](image-2.png)

如果虚拟页对应的页表的条目中的有效位被设置，说明对应的虚拟页已缓存到物理内存中，地址字段中的地址指向物理页的起始地址，页表条目中的有效位未设置，又有两种情况：

1. 地址字段为空，对应的虚拟页未分配
2. 地址不为空，虚拟页已分配未缓存，地址字段指向磁盘中页的起始地址

<!-- CPU生成一个虚拟地址，MMU根据虚拟地址去页表中查询，如果已缓存，使用查询到的物理地址从主存取数据返回到CPU，虚拟页未缓存，则触发缺页异常，由操作系统内核中的缺页异常处理程序替换页，然后重新执行触发缺页异常的指令。 -->

CPU 生成虚拟地址，内存管理单元中的地址翻译硬件在页表中查询虚拟地址对应的虚拟页，如果对应的虚拟页已经缓存到了物理内存中，地址翻译硬件返回虚拟地址对应的物理地址，内存管理单元使用物理地址访问主存, 主存返回数据给 CPU。如果对应的虚拟页未缓存,则会触发缺页异常,调用内核中的异常处理程序,在主存中选中一个替换页,把磁盘上的的虚拟页替换到主存中，然后重新执行触发缺页异常的指令。

## 地址翻译的详细过程

N 位的虚拟地址分成两个部分，P 位的虚拟地址偏移和 N-P 位的虚拟页号。M 位的物理地址也分成两个部分，P 位的物理地址偏移和 M-P 位的物理页号，物理页和虚拟页的大小相等，对应的页的虚拟地址偏移页相等(TODO: 图片)。
在页表中的地址字段存储物理页号。CPU 生成一个虚拟地址 VA，MMU 在页表中找到虚拟地址对应的页表条目，如果页表条目中的有效位已设置，取出地址字段的物理页号，和虚拟地址中的虚拟地址偏移串联就得到了物理地址。

## 多级页表

在上面的讨论中，我们假设操作系统只维护着一个页表，磁盘空间等价于虚拟地址空间，但实际上，它们之间的关系应该是这样的：
![alt text](image-5.png)

虚拟地址空间是每个进程都有的映射关系，把虚拟地址空间的区域和磁盘对象关联起来实现了内存映射。操作系统位每个进程提供了一个独立的页表，页表维护着虚拟地址空间和物理空间之间的映射关系。
一个 32 位的虚拟地址空间的大小是 4GB，假设页面的大小是 4KB，PTE 是 4B，页表的大小是 4MB，即使一个应用只使用了 4GB 地址空间中很小的一部分，也需要一个 4MB 的页表常驻内存，这显然是对内存空间的极大浪费。
为了压缩页表，减少对内存空间不必要的损耗，我们使用层次结构的页表，页表指向的不再是页，而是一个 4MB 的片，1 个 4MB 的片包含 1024 个连续的页。只要 1024 个 PTE 就能覆盖整个地址空间。这个页表我们称之为一级页表，如果片中的空间没有被分配，一级页表中对应的 PTE 为空，如果片中有分配的页，那么一级页表中的对应的 PTE 指向二级页表的基址，二级页表中包含 1024 个 PTE，每个 PTE 对应页表中的页。

## 内存映射

磁盘上的对象关联到虚拟内存的一个区域，被加载到物理内存中。要么作为共享对象，要么作为私有对象，如果作为共享对象，那么这个进程对这个对象的写操作对拥有这个对象的其他进程也都可见。
![alt text](image-6.png)
对私有对象，使用写时复制技术。把磁盘对象加载到内存的一个区域，并把这个区域标记为只读的，设置写时复制标志，不同的进程共享对象在物理内存中的同一副本。在一个进程尝试对对象进行写操作时，因为区域的只读权限而触发保护异常，内核的异常处理程序检测到是对一个写时复制区域的写操作引起的异常，就把要进行写的页复制一份到内存中，修改进程中要修改的页的地址，重新执行触发异常的指令。
